Observações da medição inicial:
- **Memória estável** nos 60 s (53 MB / 36 MB, flat) — consistente com `frame.close()`/`bitmap.close()`; o teste de 10 min do humano é o que fecha o critério.
- O `tauri::ipc::Channel` desta versão (2.12.4) entregou o `Vec<u8>` como **array JSON de números** no frontend (diagnosticado via linhas `DEBUG` do CSV), não como ArrayBuffer binário — o protótipo converte no recebimento. Isso explica o overhead do IPC: o binário puro seria ~3–5× menor em tráfego/parse. Vale confirmar com a versão de Tauri que o produto usará.
- Ambos os modos zeram a janela ao parar (linha FIM); fps medido = quadros desenhados no canvas por 10 s.
- CPU/GPU reais do processo (decode HW? quantos núcleos?) agora saem do `run-s5.ps1` (delta de CPU por PID + `\GPU Engine(*)\Utilization Percentage` filtrando `pid_<PID>`) — pendente do passo humano.

## Notas de implementação (protótipo em `spikes/s5/`)
- App Tauri 2 + React 19 **separado** de `desktop/` (own `pnpm-lock.yaml`, `--ignore-workspace`; `src-tauri` com `[workspace]` próprio — fora do workspace raiz).
- `lc-testkit = { path = "../../../crates/lc-testkit" }` no `src-tauri/Cargo.toml` (caminho relativo a 3 níveis; a linha `../../crates/...` do cartão vale a partir de `spikes/s5/`).
- Rust: `split_access_units` + `is_idr` (flag keyframe no wire); pacing 30 fps com correção de drift; wire = `[1B flags][8B u64 LE unix-ms][payload]`.
- Automação: `s5-spike.exe --auto A|B --seconds N [--json <arq>]` inicia sozinho; com `--json` grava o resumo final (fps, drops, MB/s, latência p50/p95, memória, PID) e o app sai sozinho (frontend chama `auto_finish`; watchdog em `lib.rs` força `exit(2)` após N+30 s se não sair). `--mode` segue como alias; sem `--json` grava `spikes/s5/medicoes.csv` (executar da raiz do repo).
- Coleta: `spikes/s5/run-s5.ps1 -Mode A|B -Dpi 100|150|200 [-Minutes n | -Seconds n]` orquestra a execução: sobe o app em modo auto, monta a árvore de processos (principal + `msedgewebview2`, até 3 níveis, refeita a cada 5 s — o pool do WebView2 troca renderers durante a execução), amostra a cada 1 s CPU principal/árvore (delta de `.CPU`) e memória, e grava `docs\spikes\tmp\s5-<modo>-<dpi>.csv`. `-Dpi` é **só rótulo** — o script nunca altera a escala do Windows.
- GPU: medida por `spikes/s5/gpu-sample.ps1` em **processo separado** — nesta máquina, chamar `Get-Counter` (PDH) no mesmo processo que faz `Get-Process`/`Stop-Process` torna o app invisível para a enumeração de processos (provider NVIDIA). O filho escreve 1/s `idx|instância|valor|<unix-ms>` (streaming com flush por linha) e o pai alinha por timestamp, filtrando as instâncias `pid_<PID>_` da árvore. Contador sem resposta vira `n/a` com o motivo — nunca inventado. Uma amostra inválida do PDH (engine do alvo some entre samples; `CounterApiError`) é tolerada — os samples válidos seguem.
- `tauri.conf.json`: sem `devUrl`/`beforeDevCommand` — o exe de debug carregava `http://localhost:1420` (tauri-macro `dev: cfg!(not(feature="custom-protocol"))`, feature fora dos defaults); agora `dist/` fica embutido em todo build. Após mudar o frontend: `pnpm build` → `cargo clean -p s5-spike` → `cargo build` (em `spikes/s5/src-tauri`).
- Curiosidades do ambiente: no rustc 1.99 `Range<usize>` **não é mais `Copy`**; no Win11 24H2 `GetProcessMemoryInfo` saiu do `psapi.dll` (usar `K32GetProcessMemoryInfo` do kernel32, struct 64-bit com campos u64).
