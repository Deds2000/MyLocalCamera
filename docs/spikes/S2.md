# Spike S2 — Canal Frame Server ↔ app

Data: 2026-10-28 · PC: PC (Windows 11, RTX 3090)
Cartão: `docs/tasks/fase-0/F0-S2.md` · Protótipos: `spikes/s2/` (pipe-server, shm-server, dll, medidores)
Roteiro da parte manual: `spikes/s2/ROTEIRO-HUMANO.md`

## Conta usada pelo Frame Server (como confirmado)

- Serviço **FrameServer** (`C:\Windows\System32\svchost.exe -k Camera`), modo
  de inicialização **demanda** (confere com `sc qc FrameServer` +
  `Get-CimInstance Win32_Service`).
- Conta: **NT AUTHORITY\LocalService** (SID **S-1-5-19**) — confirmado via
  `sc qconfig FrameServer` (SERVICE_START_NAME) e `Win32_Service.StartName`.
- Sessão: quando ativo, roda na **sessão 0**; o usuário atual está na sessão 1
  → o canal precisa ser visível **entre sessões** (e o pipe, por ser objeto
  de sistema, já é).

## Achados empíricos (agente, usuário comum sem elevar)

1. **Pipe é máquina-wide**: named pipes ficam fora dos namespaces por sessão
   `Global\`/`Local\` (Microsoft Learn — *Kernel object namespaces* e
   *Named Pipes*: "Named pipes are available to all users of the local
   system"). Consequência: o Frame Server (sessão 0) **pode** abrir o pipe
   criado pelo usuário comum (sessão 1), desde que a DACL permita.
2. **Criar memória mapeada em `Global\` é negado** para usuário comum
   (`CreateFileMappingW` → **ERROR_ACCESS_DENIED**, bin `priv-test` do
   pipe-server; `s2-shm-server --ns global` → exit 2, `created:false`).
   Criar **evento** em `Global\` (`CreateEventW`) **succeeds** — o privilégio
   `SeCreateGlobalPrivilege` se aplica a file mappings/symlinks, não a eventos.
3. **SDDL do pipe**: o parser desta máquina **rejeita** SDDL sem as seções
   owner/group (erro 87). Formato que funciona:
   `O:<sid> G:<sid> D:(A;;0x1F01FF;;;<usuario>)(A;;0x1F01FF;;;S-1-5-19)`.
   SID vazio → erro 1337 (bin `sddl-test`).
4. **Prefixo de namespace é sensível a caixa**: tem que ser `Global\`/`Local\`
   exatamente (minúsculo → objeto literal → ERROR_PATH_NOT_FOUND).
5. **Opção de reversão de papéis (não adotada no protótipo)**: a DLL roda como
   LocalService e **tem** `SeCreateGlobalPrivilege`; se a DLL criar o mapa
   `Global\` e o app do usuário apenas **abrir** (open não exige privilégio),
   a shm funcionaria para usuário comum. Ficou registrada como alternativa
   para o ADR 0003.

## Veredito

**Pendente** — o agente recomenda **pipe** (namespace máquina-wide + DACL para
LocalService; criação sem privilégio; latência p50 ~0,8 ms a 93 MB/s). A
shm em `Global\` **não é criável** por usuário comum (achado 2), o que a
descarta para o cenário principal; a reversão de papéis (achado 5) é a única
via que a salvaria. O veredito final e o ADR 0003 saem depois que o humano
devolver as tabelas (cartão, passo 7).

## Riscos restantes

- **Pipe: 1 mensagem = 3,1 MB em pipe de modo mensagem** — o buffer do pipe
  precisa caber a mensagem inteira; se o app ficar lento, o backpressure
  trava o app (não o Frame Server). Aceitável para o spike; no produto, o
  protocolo de Fase 1 já usa mensagens pequenas.
- **DLL com 1 thread de leitura**: enquanto o pipe está ocupado, o `RequestSample`
  blita o último quadro (sem perda de fluxo); queda de app → fallback ao
  padrão de teste (comportamento desejado, testar no ROTEIRO §2).
- **DACL fixa em 2 SIDs** (usuário atual + LocalService): outro usuário do
  mesmo PC fica de fora — é o comportamento de segurança esperado (negado).
- **Reboot/lifetime System da câmera**: recriar o objeto entre sessões fica
  para a Fase 4 (F4-T05/T06).
- Se o Frame Server estiver **parado** (sem consumidor), a DLL não existe e o
  pipe fica sem cliente: o app precisa tratar "sem consumidor" (placeholder)
  — já está no plano da Fase 4.
