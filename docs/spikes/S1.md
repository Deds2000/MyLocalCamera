# Spike S1 — Câmera virtual × NVIDIA Broadcast

**Data:** 2026-10-28 · **PC:** Windows 11 (10.0.22621) · **GPU:** RTX 3090 · **Driver NVIDIA:** 617.14 · **NVIDIA Broadcast:** instalado (versão não registrada) · **Media source:** sample Microsoft `SimpleMediaSource` (padrão de teste), lifetime System, acesso CurrentUser

## Procedimento realizado (resumo)

1. Sample `microsoft/Windows-Camera` → `Samples/VirtualCamera` compilado (Release x64) — artefatos em `spikes/s1/_vendor/.../x64/Release/` (detalhes em `spikes/s1/NOTAS.md`).
2. **Achado do install:** a DLL do sample **não exporta `DllRegisterServer`** (só `DllGetClassObject`/`DllCanUnloadNow`) → `regsvr32` falha (exit 4). O registro correto (README do sample, passo 4; o MSI usa `vsdrfDoNoRegister`) é escrever `HKLM\SOFTWARE\Classes\CLSID\{7B89B92E-FE71-42D0-8A41-E137D06EA184}\InprocServer32` com `(default)=caminho da DLL` e `Threading=Both`. Scripts `install.ps1`/`uninstall.ps1` corrigidos para isso.
3. DLL copiada para `C:\Program Files\LocalCameraSpike\` (Frame Server roda como outro usuário → caminho máquina).
4. Câmera virtual **`SWVCamMediaSource`** criada via `VirtualCamera_Installer.exe` (register → SimpleMediaSource → System → CurrentUser).
5. Padrão de teste do sample confirmado no código: gradiente vertical (uma constante por linha, rolando 1 linha/s) com **modo de cor azul por padrão** (`m_rgbMask = COLORMODE_BLUE`, `SimpleMediaStream.h`) — o "gradiente azul" nos apps é o esperado, não bug.

## A DLL precisa de assinatura? (testado sem e com assinatura de teste)

**Não foi necessário** — a DLL do sample **sem assinatura** (build local, sem certificado de teste) funcionou em todos os apps testados, incluindo o NVIDIA Broadcast. O sample foi criado com lifetime System + acesso CurrentUser e a enumeração/uso por apps de terceiros funcionaram normalmente. Para o produto (Fase 4) a assinatura continua sendo uma decisão de distribuição, não um pré-requisito técnico.

## Riscos restantes e decisão para a Fase 4

- **Fase 4 usa Media Foundation:** `MFCreateVirtualCamera` + nossa própria media source (a DLL do produto substitui o `SimpleMediaSource` do sample com o feed real do Frame Server). **Sem fallback DirectShow.**
- **Installer do produto** deve: (1) instalar a DLL em caminho máquina (`C:\Program Files\...` — a DLL é carregada pelo Frame Server, outro usuário); (2) registrar o CLSID **gravando o registro** (`HKLM\SOFTWARE\Classes\CLSID\{GUID}\InprocServer32`, `(default)` + `Threading=Both`) — **não** `regsvr32` (a DLL do sample não exporta `DllRegisterServer`; a nossa deve seguir o mesmo modelo); (3) criar/remover a câmera via `MFCreateVirtualCamera` (P/Invoke, como o `uninstall.ps1` deste spike já faz).
- **Riscos para validar na Fase 4:** uso simultâneo por 2+ apps; ciclo de vida do Broadcast (abrir/fechar/efeitos); comportamento quando o celular cai (media source precisa entregar frames "mortos" ou sinalizar erro sem derrubar o app consumidor).
- **Assinatura de driver:** não é pré-requisito (testado sem) — decisão de distribuição adiada.
