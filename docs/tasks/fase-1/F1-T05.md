# F1-T05 — Confiança: chaves, hashes e armazenamento atômico

**Fase:** 1 · **Executor:** agente · **Depende de:** F1-T04a · **Tempo:** ~3 h · **Contexto estimado:** ~10k tokens

## Objetivo
Módulo `trust` da `lc-server`: gerar e guardar `pcId`, token de pareamento e dispositivos confiáveis (só o **hash** da chave), com comparação em tempo constante e persistência atômica e resiliente.

## Leia só isto
`docs/CHEATSHEET.md` (seção Credenciais). Nada mais.

## Contexto embutido
- Token de pareamento = **16 bytes aleatórios → 32 hex**. `deviceKey` = **32 bytes → 64 hex**. `pcId` = UUID v4.
- O PC guarda **SHA-256 (hex)** da `deviceKey`; a chave em claro **nunca** é gravada nem logada.
- Aleatoriedade: gerador do **sistema operacional** (`getrandom`).
- Comparar segredos com `subtle::ConstantTimeEq`.
- Arquivo: `<data_dir>/trust.json`, com `schemaVersion: 1`.
- Se o arquivo estiver corrompido (JSON inválido, vazio, `schemaVersion` futuro): renomear para `trust.json.corrupt-<unix_ts>` e **recriar** do zero (novo `pcId`/token; dispositivos perdidos). Nunca derrubar o app.

## Passos
1. Dependências: `cargo add -p lc-server serde --features derive`, `serde_json`, `sha2`, `subtle`, `getrandom`, `hex`, `uuid --features v4`; dev: `tempfile`.
2. `secrets.rs`:
   ```rust
   pub fn random_hex(bytes: usize) -> String;         // OS RNG
   pub fn sha256_hex(input: &str) -> String;
   pub fn ct_eq(a: &str, b: &str) -> bool;            // false se tamanhos diferem; sem panic
   ```
3. `store.rs` — dados e API:
   ```rust
   #[derive(Serialize, Deserialize, Clone)]
   pub struct TrustedDevice { pub device_id: String, pub name: String, pub key_hash: String,
                              pub first_seen: u64, pub last_seen: u64, pub last_ip: String }
   pub enum VerifyDevice { Ok, Unknown, BadKey }       // Unknown = não cadastrado ou revogado
   pub struct TrustStore { /* path, data: Data, Mutex ou &mut */ }
   impl TrustStore {
       pub fn open(dir: &Path) -> Result<Self, TrustError>;   // cria/recupera
       pub fn pc_id(&self) -> &str;
       pub fn pair_token(&self) -> &str;
       pub fn regenerate_token(&mut self) -> Result<String, TrustError>;
       pub fn verify_pair_token(&self, token: &str) -> bool;
       /// Cadastra e devolve a deviceKey (64 hex) **uma única vez**.
       pub fn add_device(&mut self, device_id: &str, name: &str, ip: &str, now: u64) -> Result<String, TrustError>;
       pub fn verify_device(&self, device_id: &str, key: &str) -> VerifyDevice;
       pub fn touch(&mut self, device_id: &str, ip: &str, now: u64) -> Result<(), TrustError>;
       pub fn revoke(&mut self, device_id: &str) -> Result<bool, TrustError>;
       pub fn list(&self) -> Vec<TrustedDevice>;
   }
   ```
   `now` é injetado (segundos Unix) para testes determinísticos. Todo método que altera estado **grava** o arquivo.
4. **Escrita atômica:** `fn write_atomic(path: &Path, bytes: &[u8]) -> io::Result<()>`: grava em `trust.json.tmp` na mesma pasta, `sync_all`, depois `std::fs::rename` sobre o destino. Para o teste de falha, crie uma variante `write_atomic_with(path, bytes, hook: impl FnOnce() -> io::Result<()>)` onde `hook` roda **entre** a escrita do temporário e o `rename` (o teste faz o hook falhar).
5. Recuperação: em `open`, se o arquivo existir mas não for válido → renomear para `trust.json.corrupt-<ts>` e criar novo; se `schemaVersion > 1` → idem.
6. **Logs:** nunca use `{:?}` em structs que contenham segredos; implemente `Debug` manual de `TrustStore` que **omite** token e hashes.
