# F1-T04b — Servidor: handshake, autenticação e negociação de versão

**Fase:** 1 · **Executor:** agente · **Depende de:** F1-T04a, F1-T05, F1-T09a · **Tempo:** ~4 h · **Contexto estimado:** ~13k tokens

## Objetivo
Implementar o **HELLO → WELCOME** completo: validação de versão, autenticação (`pair` e `device`), sessão única (`busy`/substituição), emissão de `sessionId` e `audioTicket`, e proteção contra mensagens fora de ordem. A decisão de **aprovação** ainda é um *stub* (resolvido no F1-T06).

## Leia só isto
`docs/CHEATSHEET.md` (reasons, limites, credenciais). Nada mais.

## Contexto embutido
**Fluxo (primeiro quadro da conexão):**
1. Primeiro quadro **deve** ser `HELLO` (ou, no socket de áudio, `AUDIO_HELLO` — ver F1-T09b; aqui `AUDIO_HELLO` é recusado com `bad_audio_ticket`). Qualquer outra mensagem antes do WELCOME → fechar com `ProtocolError` (nenhuma resposta).
2. **Versão:** `protocol.major != 1` → `WELCOME{accepted:false, reason:version_mismatch, minSupported:{1,0}}` e fechar. `minor` diferente é aceito.
3. **Auth `pair`:** token inválido → `bad_token` (e registrar falha — ver F1-T15). Token válido → decisão de aprovação (stub: se `cfg.auto_approve`, `ApproveAlways`; senão `Reject` → `not_approved`).
   - `ApproveAlways` → `trust.add_device(...)` e **WELCOME com `deviceKey`**; `ApproveOnce` → WELCOME **sem** `deviceKey`. Em ambos, **rotacionar** o token de pareamento.
4. **Auth `device`:** `verify_device`: `Ok` → aceita (atualiza `last_seen`/`last_ip`; **sem** `deviceKey` no WELCOME); `Unknown` → `revoked`; `BadKey` → `bad_token`.
5. **Sessão única:** se já há sessão ativa de **outro** `deviceId` → `busy`. Do **mesmo** `deviceId` → a antiga recebe `BYE{reason:"replaced"}` e é encerrada com `CloseReason::Replaced`; a nova prossegue.
6. **WELCOME aceito:** `{accepted:true, protocol:{1,0}, sessionId (16 bytes hex), audioTicket (de TicketStore.issue), deviceKey?, pc:{id,name,appVersion}}`. Estado da conexão → `Active`; liberar o *permit* de não autenticadas.
7. `PING` em sessão ativa → responder `PONG` com o mesmo `u64`. `BYE` → encerrar. Demais mensagens: ignorar com log (serão tratadas no F1-T10/Fase 3).
8. `HELLO` **de novo** numa conexão já autenticada → `ProtocolError`.

## Passos
1. `config.rs`: acrescente `pub auto_approve: bool` (padrão `false`; `for_tests` aceita parâmetro) e `pub approval_timeout: Duration` (30 s).
2. `version.rs`:
   ```rust
   pub const SERVER_PROTOCOL: ProtocolVersion = ProtocolVersion { major: 1, minor: 0 };
   pub fn negotiate(client: &ProtocolVersion) -> Result<(), ProtocolVersion /* minSupported */>;
   ```
   (`Ok` se `client.major == SERVER_PROTOCOL.major`).
3. `sessions.rs`: registro de sessão ativa (`Mutex<Option<ActiveSession>>` onde `ActiveSession { session_id, device_id, conn_id, kick: oneshot::Sender<()> }`), com `claim(device_id) -> Claim::{Granted{kicked: bool}, Busy}`; `release(session_id)`.
4. `handshake.rs`: função assíncrona `perform(ctx, hello, peer) -> Outcome` (`Accepted{session, device_name,...}` | `Denied{reason, min_supported}` | `Close(CloseReason)`), seguindo o fluxo acima. **Não** use `unwrap()`.
5. `events.rs`: novos eventos `SessionStarted { conn_id, session_id, device_id, device_name, peer, caps: Caps }` e `SessionEnded { session_id, reason: CloseReason }`.
6. `conn.rs`: integrar — em `AwaitHello`, ao ler o 1º frame: `Message::from_frame`; erro → `ProtocolError`; `Hello` → `perform`; envie o `WELCOME` (`Message::Welcome(...).encode`) e, se negado, feche **após** enviar. Depois de `Accepted`, entre no laço de sessão (item 7).
7. `tests/common/mod.rs`: `struct TestClient { stream, reader }` com `connect(port)`, `send(&Message)`, `send_raw(&[u8])`, `recv(timeout) -> Option<Message>` (usa `FrameReader` + `Message::from_frame`) e helpers `hello_pair(token, device_id)` / `hello_device(device_id, key)`.
