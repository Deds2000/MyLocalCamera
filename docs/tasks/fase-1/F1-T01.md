# F1-T01 — Vetores de teste do protocolo (`docs/protocol-vectors.json`)

**Fase:** 1 · **Executor:** agente · **Depende de:** F0-GATE · **Tempo:** ~2 h · **Contexto estimado:** ~9k tokens

## Objetivo
Criar o arquivo de vetores (bytes em hex + resultado esperado) que **Rust, TypeScript e Kotlin** vão executar, e um validador que checa a coerência do próprio arquivo. Os vetores são escritos **à mão** (independentes da implementação) para pegar erros de interpretação.

## Leia só isto
`docs/CHEATSHEET.md` (tabela do cabeçalho e dos tipos). Nada mais.

## Contexto embutido
Cabeçalho (18 bytes, little-endian): `43 4C` (magic) · `type` · `flags` · `stream` · `00` (reserved) · `pts` (8 bytes) · `length` (4 bytes). Depois, `length` bytes de payload.
Exemplo `PING` (tipo `0x30`), `pts=0`, payload `u64=1`:
`43 4c 30 00 00 00 | 00 00 00 00 00 00 00 00 | 08 00 00 00 | 01 00 00 00 00 00 00 00` (26 bytes).
`length` máximo = 8 MiB = `0x00800000` → bytes `00 00 80 00`. Acima disso = erro `TooLarge`.
`ptsUs` vai como **string decimal** no JSON (u64 não cabe em número JS).

## Passos
1. Crie `docs/protocol-vectors.json` com esta estrutura (`hex` aceita espaços; os loaders removem espaços):
   ```json
   {
     "schemaVersion": 1,
     "frames": [
       { "name": "ping_pts0",
         "hex": "43 4c 30 00 00 00  00 00 00 00 00 00 00 00  08 00 00 00  01 00 00 00 00 00 00 00",
         "expect": { "frames": [ { "typeCode": 48, "type": "PING", "flags": 0, "stream": 0, "ptsUs": "0", "payloadHex": "0100000000000000" } ], "pendingBytes": 0 } },
       { "name": "video_key_pts_max",
         "hex": "43 4c 10 03 01 00  ff ff ff ff ff ff ff ff  03 00 00 00  00 00 01",
         "expect": { "frames": [ { "typeCode": 16, "type": "VIDEO", "flags": 3, "stream": 1, "ptsUs": "18446744073709551615", "payloadHex": "000001" } ], "pendingBytes": 0 } },
       { "name": "request_keyframe_empty_payload",
         "hex": "43 4c 40 00 01 00  00 00 00 00 00 00 00 00  00 00 00 00",
         "expect": { "frames": [ { "typeCode": 64, "type": "REQUEST_KEYFRAME", "flags": 0, "stream": 1, "ptsUs": "0", "payloadHex": "" } ], "pendingBytes": 0 } },
       { "name": "unknown_type_then_ping",
         "hex": "43 4c 99 00 00 00  00 00 00 00 00 00 00 00  03 00 00 00  aa bb cc  43 4c 30 00 00 00  00 00 00 00 00 00 00 00  08 00 00 00  01 00 00 00 00 00 00 00",
         "expect": { "frames": [ { "typeCode": 153, "type": "UNKNOWN", "flags": 0, "stream": 0, "ptsUs": "0", "payloadHex": "aabbcc" }, { "typeCode": 48, "type": "PING", "flags": 0, "stream": 0, "ptsUs": "0", "payloadHex": "0100000000000000" } ], "pendingBytes": 0 } },
       { "name": "two_frames_glued",
         "hex": "43 4c 30 00 00 00  00 00 00 00 00 00 00 00  08 00 00 00  01 00 00 00 00 00 00 00  43 4c 40 00 01 00  00 00 00 00 00 00 00 00  00 00 00 00",
         "expect": { "frames": [ { "typeCode": 48, "type": "PING", "flags": 0, "stream": 0, "ptsUs": "0", "payloadHex": "0100000000000000" }, { "typeCode": 64, "type": "REQUEST_KEYFRAME", "flags": 0, "stream": 1, "ptsUs": "0", "payloadHex": "" } ], "pendingBytes": 0 } },
       { "name": "max_length_header_only_waits",
         "hex": "43 4c 10 00 01 00  00 00 00 00 00 00 00 00  00 00 80 00",
         "expect": { "frames": [], "pendingBytes": 18 } },
       { "name": "bad_magic",
         "hex": "58 58 30 00 00 00  00 00 00 00 00 00 00 00  00 00 00 00",
         "expect": { "error": "BadMagic" } },
       { "name": "too_large_by_one",
         "hex": "43 4c 10 00 01 00  00 00 00 00 00 00 00 00  01 00 80 00",
         "expect": { "error": "TooLarge" } }
     ],
     "json": []
   }
   ```
2. Acrescente à lista `"json"` os vetores de mensagens JSON (cada item: `name`, `message` (nome do tipo), `json` (objeto) e `expect` = `"ok"` ou `"BadJson"`). **Casos obrigatórios:**
   - `hello_pair`: `{"protocol":{"major":1,"minor":0},"app":{"version":"0.1.0","platform":"android"},"device":{"id":"11111111-1111-4111-8111-111111111111","name":"Pixel","model":"Pixel 8","androidApi":35},"auth":{"kind":"pair","token":"00112233445566778899aabbccddeeff"},"caps":{"cameras":[{"id":"0","facing":"back","modes":[{"w":1920,"h":1080,"fps":[30]}]}],"concurrent":false,"audio":true,"codecs":["h264"]}}` → `ok`
   - `hello_device`: igual, com `"auth":{"kind":"device","deviceId":"11111111-1111-4111-8111-111111111111","key":"<64 hex>"}` → `ok`
   - `hello_extra_fields`: `hello_pair` com um campo extra `"futuro":{"x":1}` na raiz e dentro de `device` → `ok`
   - `hello_missing_auth`: sem `auth` → `BadJson`
   - `hello_bad_auth_kind`: `"auth":{"kind":"magic"}` → `BadJson`
   - `hello_wrong_type`: `"protocol":"1.0"` → `BadJson`
   - `welcome_ok`: `{"accepted":true,"protocol":{"major":1,"minor":0},"sessionId":"s1","audioTicket":"aa","pc":{"id":"p1","name":"PC","appVersion":"0.1.0"}}` → `ok`
   - `welcome_denied_each_reason`: um vetor por `reason` (`bad_token`,`not_approved`,`revoked`,`busy`,`version_mismatch`,`bad_audio_ticket`,`timeout`,`protocol_error`) → `ok`
   - `welcome_unknown_reason`: `"reason":"algo_novo"` → `ok` (interpretado como "outro")
   - `state_basic`: `{"rev":1,"camera":{"mode":"single","active":"back"},"video":{"width":1920,"height":1080,"fps":30,"bitrateKbps":8000},"presentation":{"mirror":{"back":false,"front":false},"rotation":{"back":0,"front":0}},"audio":{"enabled":true,"gain":1.0}}` → `ok`
   - `state_missing_rev`: sem `rev` → `BadJson`
   - `set_single`: `{"key":"camera.active","value":"front"}` → `ok`
   - `set_list`: `[{"key":"video.fps","value":30},{"key":"video.width","value":1280}]` → `ok`
   - `stream_config_basic`: `{"stream":1,"width":1920,"height":1080,"fps":30,"rotationHint":90,"facing":"back"}` → `ok`
   - `audio_hello_basic`: `{"sessionId":"s1","ticket":"aa"}` → `ok`
   - `stats_basic`: `{"recvFps":29.9,"dropped":0,"queueMs":12}` → `ok`
   - `bye_basic`: `{"reason":"busy"}` → `ok`
3. `scripts/validate-vectors.mjs`: lê o arquivo; para cada item de `frames`, remove espaços do `hex`, converte para bytes e **confere**: se `expect.frames` existir, soma `18 + payload.length` de cada frame esperado e compara com o total de bytes (descontando `pendingBytes`) e checa que o `magic` das frames esperadas é `43 4c`; checa que não há `name` duplicado e que todo item tem `expect`. Em caso de erro, imprime o nome do vetor e `process.exit(1)`.
4. Rode a validação.

## Testes a escrever
Este cartão **só** cria os vetores e o validador. Os testes que usam os vetores vêm em F1-T02a (Rust), F1-T02b (Rust, JSON) e F1-T03 (TypeScript).

## Verificação
```powershell
pnpm run vectors:check
```
Saída esperada: `vetores OK: 8 de frames, N de json` (imprima as contagens) e código de saída 0. Teste de sanidade: altere um byte do `length` de um vetor e confirme que o validador **falha**; restaure.

## Não faça
- Não gere os vetores a partir do código Rust (precisam ser independentes).
- Não use números JSON para `ptsUs`.
- Não altere o formato do cabeçalho.
