# F1-T03 — Tipos e validadores TypeScript do protocolo (+ URI de pareamento)

**Fase:** 1 · **Executor:** agente · **Depende de:** F1-T01 · **Tempo:** ~2,5 h · **Contexto estimado:** ~9k tokens

## Objetivo
Em `@localcamera/shared/protocol`: constantes, schemas **zod** das mensagens JSON (rodando os vetores `json`) e as funções `buildPairingUri`/`parsePairingUri` com vetores próprios (`docs/pairing-uri-vectors.json`) que o Kotlin também usará na Fase 2.

## Leia só isto
`docs/CHEATSHEET.md` (URI, limites, reasons, estado) e a parte `json` de `docs/protocol-vectors.json`.

## Contexto embutido
- Campos desconhecidos são ignorados (comportamento padrão do zod `object`).
- `reason` desconhecido → `"other"`.
- URI: `localcamera://connect?v=1&hosts=IP1,IP2&port=48650&token=<32 hex>&pc=<id>&name=<nome>`. Regras: `v` inteiro; `v` > 1 → "incompatível"; `hosts` de 1 a 4 **IPv4**; `port` 1–65535; `token` = 32 caracteres hex; `pc` não vazio (≤ 64); `name` ≤ 64 caracteres (decodificado); parâmetros desconhecidos ignorados.

## Passos
1. `pnpm --filter @localcamera/shared add zod`.
2. `constants.ts`: `MAGIC = 0x4c43`, `HEADER_LEN = 18`, `MAX_PAYLOAD = 8 * 1024 * 1024`, `HELLO_MAX = 64 * 1024`, `DEFAULT_PORT = 48650`, `MSG` (objeto com **todos** os códigos da tabela do CHEATSHEET), `REASONS` (array `as const` dos 8 códigos), `STREAM = { control: 0, videoA: 1, videoB: 2, audio: 3 }`, `LIMITS` (tempos do CHEATSHEET em ms).
3. `schemas.ts`: schemas zod e tipos inferidos (`z.infer`) para `Hello`, `Auth` (união discriminada por `kind`), `Welcome`, `State`, `SetPayload` (`z.union([z.array(SetItem), SetItem])`), `StreamConfig`, `AudioHello`, `Stats`, `Bye`. `Reason`: `z.string().transform(v => (REASONS as readonly string[]).includes(v) ? v : "other")`. **Mesmos nomes de campo** (camelCase) do JSON dos vetores.
4. `pairing-uri.ts`:
   ```ts
   export type PairingUri = { v: number; hosts: string[]; port: number; token: string; pc: string; name: string };
   export type ParseResult =
     | { ok: true; value: PairingUri }
     | { ok: false; error: "invalid" | "incompatible_version" };
   export function buildPairingUri(p: PairingUri): string { /* hosts.join(","), encodeURIComponent(name) */ }
   export function parsePairingUri(uri: string): ParseResult { /* usar URL + URLSearchParams; validar regras */ }
   ```
5. `docs/pairing-uri-vectors.json`: lista `[{ "name", "uri", "expect": "ok" | "invalid" | "incompatible_version", "value": {...} }]` com **no mínimo** estes casos: (ok) uma URI completa com 1 host; (ok) 2 hosts; (ok) `name` com acentos e espaço codificados (`Meu%20PC%20%C3%A7`); (ok) parâmetro extra `x=1`; (invalid) sem `token`; (invalid) `token` com 31 chars; (invalid) `token` com caractere não-hex; (invalid) `port=0`; (invalid) `port=70000`; (invalid) `hosts` vazio; (invalid) host `abc`; (invalid) 5 hosts; (invalid) esquema errado `http://connect?...`; (invalid) host da URL diferente de `connect` (`localcamera://pair?...`); (incompatible_version) `v=2`; (invalid) `v=abc`.
6. Testes:
   - `schemas.test.ts`: lê `docs/protocol-vectors.json` com `node:fs` (caminho relativo ao arquivo de teste; ajuste a profundidade) e, para cada item de `json`, valida com o schema pelo campo `message`: `"ok"` → `safeParse` sucesso; `"BadJson"` → falha. Teste extra: `welcome_unknown_reason` → `reason === "other"`.
   - `pairing-uri.test.ts`: roda todos os vetores de `pairing-uri-vectors.json` (parse), e prova **ida e volta** (`parse(build(x))` igual a `x`) para os casos `ok`.
