# F1-T15 — Limitação de tentativas de autenticação e de novas conexões

**Fase:** 1 · **Executor:** agente · **Depende de:** F1-T04b · **Tempo:** ~2,5 h · **Contexto estimado:** ~8k tokens

## Objetivo
Proteger o servidor contra **força bruta de token** e **tempestade de conexões**, com relógio injetável e limites configuráveis.

## Leia só isto
`docs/CHEATSHEET.md` (falhas de autenticação). Nada mais.

## Contexto embutido
- **Falhas de autenticação:** 5 em 60 s do **mesmo IP** → bloqueio de **5 min** (conexões desse IP são fechadas **logo após o accept**, sem resposta).
- **Sucesso** zera o contador daquele IP.
- **Novas conexões:** mais de **20** do mesmo IP em **10 s** → fechar as seguintes até a janela esvaziar (sem bloqueio longo).
- Valores configuráveis em `ServerConfig` (`auth_fail_max`, `auth_fail_window`, `auth_block`, `conn_rate_max`, `conn_rate_window`) — padrões acima; testes usam valores pequenos.
- As respostas aos 5 primeiros erros são **uniformes** (`bad_token`), sem diferenciar o motivo.
- Nunca logar o token tentado.

## Passos
1. `ratelimit.rs`:
   ```rust
   pub struct AuthLimiter { /* HashMap<IpAddr, FailState> */ }
   impl AuthLimiter {
       pub fn new(max: u32, window_secs: u64, block_secs: u64) -> Self;
       pub fn is_blocked(&mut self, ip: IpAddr, now: u64) -> bool;
       pub fn record_failure(&mut self, ip: IpAddr, now: u64);
       pub fn record_success(&mut self, ip: IpAddr);
   }
   pub struct ConnRateLimiter { /* HashMap<IpAddr, VecDeque<u64>> */ }
   impl ConnRateLimiter {
       pub fn new(max: usize, window_secs: u64) -> Self;
       /// true = pode aceitar (registra a tentativa)
       pub fn allow(&mut self, ip: IpAddr, now: u64) -> bool;
   }
   ```
   Limpe entradas antigas ao consultar (sem crescer sem limite; teste de memória simples: após 10 000 IPs distintos e o tempo passar, o mapa esvazia na próxima limpeza).
2. `conn.rs`: no accept, **antes** de qualquer leitura: `if !conn_rate.allow(ip, now) || auth.is_blocked(ip, now)` → fechar com `CloseReason::RateLimited` (adicione a variante) e emitir evento.
3. `handshake.rs`: em `bad_token`/`BadKey` → `record_failure`; em sucesso → `record_success`. Um IP bloqueado **durante** o handshake (6ª falha) recebe `bad_token` na resposta daquela tentativa e é bloqueado nas seguintes.
4. Eventos: `ServerEvent::AuthBlocked { ip }` ao entrar em bloqueio.
