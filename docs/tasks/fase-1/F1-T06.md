# F1-T06 — Fluxo de aprovação (`PENDING`, timeout, decisão)

**Fase:** 1 · **Executor:** agente · **Depende de:** F1-T04b · **Tempo:** ~3 h · **Contexto estimado:** ~9k tokens

## Objetivo
Substituir o *stub* do F1-T04b pelo fluxo real: ao parear um dispositivo novo, enviar `PENDING`, emitir um evento para a UI decidir (`approve_always`, `approve_once`, `reject`), tratar timeout de 30 s e cancelamento.

## Leia só isto
`docs/CHEATSHEET.md` (aprovação 30 s; `PENDING`; reasons). Nada mais.

## Contexto embutido
- **Um pedido por vez.** Outro `HELLO` de pareamento enquanto há pedido pendente → `WELCOME{busy}`.
- Ao iniciar o pedido: enviar `PENDING{timeoutS: 30}` ao celular e emitir `ServerEvent::ApprovalRequested(ApprovalRequest)`.
- Resultados: `ApproveAlways` (grava dispositivo e entrega `deviceKey`), `ApproveOnce` (não grava), `Reject` → `not_approved`, **timeout** → `not_approved`, **celular desconectou** → pedido cancelado (evento `ApprovalResolved{Cancelled}`).
- `decide(request_id, decision)` para um `request_id` desconhecido/já resolvido é **ignorado** (devolve `false`).
- `auto_approve` só vale em **build de debug** (`cfg!(debug_assertions)`); em release é ignorado com aviso no log.

## Passos
1. `events.rs`:
   ```rust
   pub struct ApprovalRequest { pub request_id: u64, pub device_id: String, pub name: String, pub model: String, pub ip: String }
   pub enum Decision { ApproveAlways, ApproveOnce, Reject }
   pub enum ApprovalOutcome { Approved(Decision), Rejected, TimedOut, Cancelled }
   // ServerEvent ganha: ApprovalRequested(ApprovalRequest), ApprovalResolved { request_id: u64, outcome: ApprovalOutcome }
   ```
2. `approval.rs`: `ApprovalManager` com **no máximo um** pedido pendente:
   ```rust
   pub struct ApprovalManager { /* Mutex<Option<Pending{request_id, tx: oneshot::Sender<Decision>}>>, contador */ }
   impl ApprovalManager {
       pub fn begin(&self, req_info) -> Result<(u64 /*id*/, oneshot::Receiver<Decision>), Busy>;
       pub fn decide(&self, request_id: u64, d: Decision) -> bool;
       pub fn cancel(&self, request_id: u64);    // celular caiu
   }
   pub fn effective_auto_approve(flag: bool, debug_build: bool) -> bool { flag && debug_build }
   ```
3. `handshake.rs`: no ramo `Pair` com token válido (e fora da janela USB — F1-T07): se `effective_auto_approve(cfg.auto_approve, cfg!(debug_assertions))` → `ApproveAlways`; senão `begin` (se `Busy` → `WELCOME{busy}`), enviar `PENDING`, emitir `ApprovalRequested`, e `tokio::select!` entre: a decisão, `tokio::time::sleep(cfg.approval_timeout)` e a **leitura da conexão** (se o celular fechar → `cancel`, emitir `Cancelled`, encerrar). Resolva sempre com `ApprovalResolved` e remova o pedido pendente.
4. `ServerHandle`: `pub fn decide(&self, request_id: u64, d: Decision) -> bool`.
5. Durante `Pending` **não** vale o timeout de 5 s do HELLO (só o de aprovação).
