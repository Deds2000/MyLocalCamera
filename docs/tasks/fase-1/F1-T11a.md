# F1-T11a — `mock-sender`: pareamento, reconexão e vídeo/áudio

**Fase:** 1 · **Executor:** agente · **Depende de:** F1-T09b, F0-T13 · **Tempo:** ~4 h · **Contexto estimado:** ~12k tokens

## Objetivo
Uma ferramenta (`tools/mock-sender`, **lib + bin**) que **finge ser o celular**: pareia por URI, reconecta com a chave salva, envia vídeo H.264 em loop com *pacing* e áudio (seno 440 Hz) pelo socket de áudio.

## Leia só isto
`docs/CHEATSHEET.md` (URI, tipos, fluxo). Os fixtures de `fixtures/` devem existir (F0-T13).

## Contexto embutido
- Fluxo do mock: conecta (tenta `hosts` em ordem) → `HELLO` (câmera traseira 1080p30, `audio:true`) → trata `PENDING`/`WELCOME` → **STREAM_CONFIG** (stream 1, 1920×1080, 30 fps, `rotationHint` 0, `facing:"back"`) → `VIDEO` por *access unit* a 30 fps → em paralelo, abre o 2º socket com `AUDIO_HELLO{sessionId, ticket}` e envia blocos `AUDIO` de **10 ms** (480 amostras s16le = 960 bytes).
- Vídeo: usa `lc_testkit::annexb::split_access_units`; `flags` = `1` se o AU tem IDR, `+2` se tem SPS e PPS (NAL 7 e 8); `ptsUs = índice × 1_000_000 / fps`; `stream = 1`.
- Áudio: seno contínuo (acumular a fase entre blocos; sem saltos).
- Persistência: `--state-file arquivo.json` guarda `deviceId` e `deviceKey`; se existir, o mock usa `auth.kind = device` automaticamente.
- Responde `PING` com `PONG`.
- Códigos de saída: `0` ok · `2` recusado pelo servidor (imprime o `reason`) · `1` erro.

## Passos
1. Dependências:
   ```powershell
   cargo add -p mock-sender clap --features derive
   cargo add -p mock-sender serde --features derive
   cargo add -p mock-sender serde_json uuid --features v4
   cargo add -p mock-sender url hex tracing tracing-subscriber bytes thiserror
   cargo add -p mock-sender lc-protocol --path crates/lc-protocol
   cargo add -p mock-sender lc-testkit --path crates/lc-testkit
   cargo add -p mock-sender --dev lc-server --path crates/lc-server
   ```
2. `uri.rs`: `parse_pairing_uri(&str) -> Result<PairingUri, UriError>` com as **mesmas regras** de `docs/pairing-uri-vectors.json` (host IPv4 ×1–4, porta, token 32 hex, `v`). **Teste com o arquivo de vetores** (caminho relativo à raiz do repo).
3. `cli.rs` (clap derive): `--uri`, `--host`, `--port` (48650), `--token`, `--device-id`, `--name` (`"Mock Phone"`), `--state-file`, `--device-key`, `--file`, `--loop`, `--fps` (30), `--audio`, `--tone` (440), `--seconds` (duração; sem valor = até acabar o arquivo ou Ctrl+C). `--uri` e (`--host`+`--token`) são **mutuamente exclusivos**.
4. `state_file.rs`: `load(path)`/`save(path, &State)` com `{deviceId, deviceKey}` (arquivo de teste, texto simples — é só mock).
5. `session.rs`: `pub async fn run(cfg: MockConfig) -> Result<Summary, MockError>`:
   - conectar; enviar HELLO; aguardar WELCOME (aceitando `PENDING` antes); `accepted=false` → `Err(Denied(reason))`;
   - se o WELCOME trouxer `deviceKey` e houver `--state-file`, salvar;
   - enviar `STREAM_CONFIG`; lançar tasks: **leitura** (PING→PONG, BYE, contagem de mensagens), **vídeo** e **áudio**;
   - `Summary { video_frames, video_bytes, audio_blocks, closed_by: Option<String>, session_id }`.
6. `video.rs`: leitura do arquivo → AUs → `interval` de `1/fps` (use `MissedTickBehavior::Delay`) → envia `VIDEO`; `--loop` reinicia (continuando `pts`). **Sem arquivo e sem `--audio`**, o mock só pareia e fica conectado respondendo PING até `--seconds`.
7. `audio.rs`: gerador `SineGen { phase, freq, rate }` com `next_block(n_samples) -> Vec<u8>`; task que envia 1 bloco a cada 10 ms (`interval`), com `pts` crescente; abre o socket de áudio **depois** do WELCOME usando `audioTicket`.
8. `main.rs`: parse CLI, `tracing_subscriber` (nível por `RUST_LOG`), chama `run`, imprime o `Summary` em uma linha legível e retorna o código de saída.
9. `README.md`: tabela de flags desta fase e 4 exemplos de uso (parear; reconectar com `--state-file`; só áudio; vídeo em loop por 30 s).
