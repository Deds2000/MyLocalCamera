# F2-T05 — `PairingStore.kt` (deviceId, PCs conhecidos, `deviceKey`)

**Fase:** 2 · **Executor:** A+H · **Depende de:** F2-T01 · **Tempo:** ~4 h · **Contexto estimado:** ~12k tokens

## Objetivo
Os dados persistentes do celular: `deviceId` estável (UUID, gerado uma vez), lista de PCs conhecidos (`pcId`, nome, `hosts`, `porta`, último acesso) e a `deviceKey` (256 bits) em armazenamento privado do app, **excluída do backup**, com a chave ausente de logs e `toString`.

## Leia só isto
`docs/CHEATSHEET.md` (seções Credenciais e Nomes). `docs/protocol.md` §6 (credenciais: token 128 bits; `deviceKey` 256 bits; o PC guarda só o SHA-256). `mobile/android/app/src/main/AndroidManifest.xml` (já tem `allowBackup="false"`).

## Contexto embutido
- **Pesquise antes de codar (não invente API):** docs oficiais do Android (Android Keystore / `KeyGenParameterSpec` / AES-GCM). Algumas bibliotecas de armazenamento seguro foram descontinuadas — risco §9 da fase: contingência = **usar o Keystore diretamente com criptografia própria mínima** (AES-GCM, chave no `AndroidKeyStore`, sem exportar). Registre a escolha escolhida em comentário de código.
- `allowBackup="false"` já exclui o app do backup do Android — confirme em build com `adb backup` (ST-2.01).
- A chave nunca vai para log (máx. 4 chars) nem para `toString`/`Debug` das classes de dados.
- `forget(pcId)` apaga o PC **e** a chave. Ao receber `revoked` (F2-T09), apagar só a chave (o PC fica na lista).
- PCs conhecidos **não** são segredo → JSON plano em arquivo privado do app (escrita atômica: temp + rename). A `deviceKey` vai pela `SecureStore`.

## Passos
1. Pesquise a API de Keystore recomendada para `targetSdk 36` (docs oficiais) e registre a decisão.
2. `SecureStore` (interface): `put(keyId: String, secret: ByteArray)`, `get(keyId): ByteArray?`, `delete(keyId)`; `KeystoreSecureStore` = AES-GCM + `AndroidKeyStore`.
3. `PairingStore(context)`: `deviceId()` (gera e persiste uma vez), `upsertPc(pc)`, `listPcs()`, `getPc(pcId)`, `forgetPc(pcId)`, `saveDeviceKey(pcId, key)`, `deviceKey(pcId)`.
4. Robustez: arquivo corrompido → loga e estado vazio (sem crash).
5. UT-2.07 (JVM, com `SecureStore` fake e diretório temporário).
6. (A+H) ST-2.01: o agente instala o APK e grava uma chave de teste; o **humano** roda `adb -s RXCT800A2HR backup -f backup.ab com.localcamera.app` (confirma o diálogo no aparelho) e devolve o arquivo; o agente extrai o `.ab` (é um zip) e busca os bytes da chave → ausentes.
