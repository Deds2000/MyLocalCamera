## Objetivo
Interface `CameraBackend` (UI/sessão **nunca** importam CameraX) + implementação CameraX (câmera única, veredito S3): `start(config, outputSurface)`, `stop()`, `switchTo(facing)`, `onRotationHint` — alimentando a `Surface` do encoder com 1080p30.

## Contexto embutido
- S3: CameraX com `Preview` + `SurfaceProvider` (superfície do encoder); fps via `Camera2Interop` (`CONTROL_AE_TARGET_FPS_RANGE` 30-30); 1080p30 estável (29,7 fps, jitter <1).
- **Armadilha (S3):** `setTargetResolution` cai em 1088×1088 → usar `ResolutionSelector` (aspecto 16:9) + alvo 1920×1080. Confirme os nomes exatos da API nos artifacts/docs oficiais antes de codar.
- Rotação: a UI fica em retrato, mas o `rotationHint` reflete a orientação do sensor + rotação do aparelho (AT-2.14 em F2-T14).
- Versionamento: CameraX já está no `build.gradle` (F2-T06) — não troque.
- Interrupções (outro app abre a câmera, chamada telefônica): `onCameraError` → evento para o chamador (FT-2.04/FT-2.05 em F2-T14).

## Esqueleto de código
```kotlin
interface CameraBackend {
    fun start(config: CameraConfig, outputSurface: Surface)
    fun stop()
    fun switchTo(facing: Facing)
    fun onRotationHint(listener: (Int) -> Unit)  // 0/90/180/270
    fun onEvent(listener: (CameraEvent) -> Unit) // started, error(codigo), rotated
}
// CameraConfig: facing, width=1920, height=1080, fps=30
```

## Passos
1. Interface + `CameraConfig` (dados mínimos; sem tipos CameraX vazando).
2. `CameraXBackend`: `ProcessCameraProvider`, `ResolutionSelector` (16:9, alvo 1920×1080 com fallback), `SurfaceProvider` apontando para a superfície do encoder, `Camera2Interop` 30-30.
3. `rotationHint`: orientação do sensor (`CameraCharacteristics.SENSOR_ORIENTATION`) + listener de rotação do device.
4. Smoke (instrumentado): start por 10 s com superfície dummy → eventos `started`, sem erro, quadros chegando (contar via callback).
