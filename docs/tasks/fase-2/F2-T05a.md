# F2-T05a — Parser da URI de pareamento (Kotlin)

**Fase:** 2 · **Executor:** A · **Depende de:** F1-GATE · **Tempo:** ~3 h · **Contexto estimado:** ~10k tokens

## Objetivo
`PairingUri.parse` em Kotlin com as mesmas regras dos parsers Rust/TS: valida `v`, `hosts` (IPv4, até 4), `port` (1–65535), `token` (32 hex), `pc`, `name`; ignora parâmetros desconhecidos; `v` maior que o suportado (1) → erro "atualize o app". Passa em `docs/pairing-uri-vectors.json`.

## Leia só isto
`docs/pairing-uri-vectors.json` (16 vetores — fonte canônica). `docs/CHEATSHEET.md` (linha do esquema de URI). Regra de referência: `packages/shared/src/protocol/pairing-uri.ts` (leia o cabeçalho dos comentários).

## Contexto embutido
- URI: `localcamera://connect?v=1&hosts=IP1,IP2&port=48650&token=<32 hex>&pc=<pcId>&name=<nome>`.
- Regras (conforme os vetores): scheme `localcamera`, host `connect`; `v` inteiro (suportado = 1; maior → `VersionTooNew` — **nunca** conectar); `hosts` 1–4 endereços IPv4 (quadros 0–255); `port` 1–65535 (padrão 48650 quando ausente); `token` exatamente 32 hex minúsculos; `pc` UUID; `name` não vazio, com limite de tamanho (seguir os vetores); parâmetros extras ignorados.
- URI malformada → erro tipado, nunca exceção/crash (ST-2.04 em F2-T14 alimenta URIs maliciosas).
- Parsing manual / `java.net.URI` — sem dependências novas.
