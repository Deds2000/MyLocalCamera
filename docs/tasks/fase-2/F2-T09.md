# F2-T09 — `PrimaryConnection.kt` (handshake, PING/PONG, backoff)

**Fase:** 2 · **Executor:** A · **Depende de:** F2-T04, F2-T05 · **Tempo:** ~5 h · **Contexto estimado:** ~14k tokens

## Objetivo
O socket principal do celular: tenta todos os `hosts` **em paralelo** (2 s cada), envia `HELLO` (`pair` ou `device`), trata `PENDING`/`WELCOME`/`reason`, guarda `deviceKey` recebida, dispara os eventos para enviar `STATE`+`STREAM_CONFIG` (F2-T12), mantém `PING/PONG`, responde `REQUEST_KEYFRAME` (callback) e reconecta com backoff 1-2-4-8-8 s (relógio injetável).

## Leia só isto
`docs/protocol.md` §3 (conexões) e §6 (handshake — 6.5/6.6). `docs/CHEATSHEET.md` (tipos, reasons, limites). `docs/protocol-vectors.json` (JSON das mensagens).

## Contexto embutido
- Fluxo mínimo (sem áudio — Fase 8): conectar → `HELLO{protocol, app, device, auth, caps}` → `PENDING{timeoutS}` (evento `pending`) ou `WELCOME`.
- `WELCOME` aceito: `{accepted:true, protocol, sessionId, pc:{id,name,appVersion}, deviceKey?}` — `deviceKey` só no pareamento aprovado com "Permitir sempre" → se vier, salvar no `PairingStore` (F2-T05) → evento `welcome` (o chamador envia `STATE` e `STREAM_CONFIG` — F2-T12).
- `WELCOME` recusado: `reason` ∈ `bad_token, not_approved, revoked, busy, version_mismatch, bad_audio_ticket, timeout, protocol_error` → evento `denied(reason)`; `revoked` → `PairingStore` apaga a chave.
- `PING` a cada 2 s (payload u64 timestamp); sem `PONG` por 6 s → conexão perdida → reconectar.
- Laço de leitura via `FrameReader` (F2-T04): tipo desconhecido já é pulado pelo codec; `BYE{reason}` → erro definitivo; `REQUEST_KEYFRAME` (payload vazio) → callback (o encoder responde em ≤300 ms — FT-2.13).
- Backoff: 1, 2, 4, 8, 8, 8… s; **reset** para 1 s após sessão bem-sucedida. Relógio injetável.
- Erros definitivos (`revoked`, `version_mismatch`) **não** reconectam; `busy`/timeout de rede reconectam.
- Versão do app no HELLO: a real do APK (`BuildConfig`/`versionName` do manifest) — não inventar.

## Passos
1. `Backoff` (puro) + sealed class `ConnectionEvent` (só códigos — nenhum texto).
2. Conexão paralela (coroutines; timeout 2 s por host; 1º sucesso vence; as perdedoras são canceladas).
3. Handshake: `HELLO` (`pair` com token | `device` com `deviceId`+chave do `PairingStore`), tratar `PENDING`/`WELCOME`, salvar `deviceKey`.
4. Pós-`WELCOME`: evento `welcome(sessionId, pc)` — quem envia `STATE`/`STREAM_CONFIG` e o vídeo é o F2-T12.
5. Tasks de `PING` (2 s) e liveness (6 s sem `PONG` → `lost`).
6. Laço de reconexão com backoff (não-definitivos); `close()` envia `BYE`.
7. UTs com socket fake + relógio virtual.
