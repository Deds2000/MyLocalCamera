# F2-T13 — `LocalCameraPlugin.kt` (plugin Capacitor)

**Fase:** 2 · **Executor:** A+H · **Depende de:** F2-T12 · **Tempo:** ~4 h · **Contexto estimado:** ~12k tokens

## Objetivo
O plugin Capacitor `LocalCamera` ligando o JS ao serviço: métodos `getCapabilities`, `connect({hosts, port, token} | {pcId})`, `disconnect`, `getState`; eventos `connectionChanged`, `stateChanged`, `stats` (≤ 2 Hz), `error` (códigos). As telas de F2-T03 passam a consumir o estado real.

## Leia só isto
`mobile/android/app/src/main/java/com/localcamera/app/service/{StreamSession,StreamEvents}.kt` (F2-T12). API de plugins do Capacitor: **leia a fonte** em `mobile/node_modules/@capacitor/android/capacitor/src` (não invente API). `docs/CHEATSHEET.md` (limite: stats ≤ 2 Hz).

## Contexto embutido
- Métodos (JS → Kotlin):
  - `getCapabilities() → caps` (probe F2-T06).
  - `connect({hosts, port, token})` (pareamento) **ou** `connect({pcId})` (PC conhecido, F2-T05; a chave vem do `PairingStore`); a URI do deep link (F2-T01) chega aqui já parseada (F2-T05a).
  - `disconnect()` → `BYE` + para o stream.
  - `getState() → AppState` (F2-T11, com `rev`).
- Eventos (Kotlin → JS): `connectionChanged{state}` (`idle|connecting|pending|streaming|reconnecting|error`), `stateChanged{state}` (F2-T11), `stats{fps, kbps, queueMs, rtt}` **≤ 2 Hz** (agregar antes de emitir), `error{code}` (**códigos** — ex.: `camera_busy`, `no_network`, `denied_bad_token`, `denied_revoked`, `app_not_visible`; nenhum texto da rede; a UI mapeia para i18n).
- Registro: anotação `@CapacitorPlugin` no Kotlin (o asset `capacitor.plugins.json` é **regenerado** pelo `cap sync` — não editar à mão). JS: wrapper tipado em `mobile/src/plugins/LocalCamera.ts` (`registerPlugin`).
- Fio das telas: `AppProvider` (F2-T03) passa a receber os eventos reais do plugin (troca o estado mock).
