# F2-T12 — `StreamingService` (foreground, notificação, composição)

**Fase:** 2 · **Executor:** A+H · **Depende de:** F2-T08, F2-T09 · **Tempo:** ~5 h · **Contexto estimado:** ~14k tokens

## Objetivo
`LifecycleService` em primeiro plano que **possui** o stream (câmera + encoder + conexão + fila + estado) e o mantém com o app em segundo plano; notificação com ação "Parar"; raiz de composição de F2-T07/08/09/10/11.

## Leia só isto
`docs/CHEATSHEET.md` (credenciais/limites). `mobile/android/app/src/main/res/values{,-pt-rBR}/strings.xml` (F2-T03b: chaves `notif_*`, `channel_streaming_*`). `docs/protocol.md` §12 (máquina de estados do celular) — só a seção.

## Contexto embutido
- **Pesquise antes de codar (não invente API):** docs oficiais do Android sobre foreground services para `targetSdk 36` (valor em `mobile/android/variables.gradle`): requisitos por versão (ex.: `foregroundServiceType` no manifest a partir do Android 14+, notificação na `startForeground` a tempo, `POST_NOTIFICATIONS` como permissão de runtime a partir do 33+). Registre as conclusões em comentário de código.
- Permissões do manifest (acrescentar): `CAMERA`, `RECORD_AUDIO` (declarada; uso na Fase 8), `ACCESS_NETWORK_STATE`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_CAMERA`, `FOREGROUND_SERVICE_MICROPHONE`, `POST_NOTIFICATIONS`, `WAKE_LOCK` (`INTERNET` já existe). No `<service>`: `android:foregroundServiceType="camera|microphone"` e `exported="false"`.
- **Armadilha (fase §6):** iniciar a transmissão **sempre com o app visível** — o Android restringe câmera a partir de segundo plano. O serviço aceita o start só quando o app está em foreground (senão, evento `error{code}` para a UI).
- Notificação: canal `streaming` (chaves `channel_streaming_*`), título/texto por `strings.xml` (placeholders `{PC}`/`{qualidade}`/`{transporte}`), ação "Parar" (`notif_action_stop`) → para o stream (a notificação some; o app segue aberto).
- `StreamSession` (a lógica, ≤300 linhas): `start(target)`/`stop()`; compõe: `CapabilitiesProbe` → `caps` do HELLO; `PrimaryConnection` (handshake, PING/PONG) + `SendQueue` + `StateReducer` + `VideoEncoder`; após `WELCOME` → `STATE` + `STREAM_CONFIG{stream:1,1920×1080,30,rotationHint,facing}` → task de vídeo (frame do encoder → `SendQueue`); `requestKeyframe` da conexão → encoder; rotação do aparelho → novo `rotationHint` no `STREAM_CONFIG` (AT-2.14); stats agregados ≤ 2 Hz para o plugin.
- O start/stop vem do plugin (F2-T13) quando o usuário toca Conectar/Parar.

1. Pesquise os requisitos de foreground service (targetSdk 36, docs oficiais) e registre.
2. Manifest: permissões + `<service ... exported="false" foregroundServiceType="camera|microphone">`.
3. `StreamSession`: a composição completa (ordem: câmera → encoder → conexão → WELCOME → STATE/STREAM_CONFIG → vídeo).

5. Smoke (instrumentado): start/stop do serviço com alvo fake → notificação criada/removida (consultar `NotificationManager`).
