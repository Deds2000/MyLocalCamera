# F2-T06 — `CapabilitiesProbe` (câmeras, modos, encoder → `HELLO.caps`)

**Fase:** 2 · **Executor:** A+H · **Depende de:** F2-T01 · **Tempo:** ~4 h · **Contexto estimado:** ~12k tokens

## Objetivo
Sonda o aparelho real e devolve o JSON `caps` do `HELLO` (formato dos vetores): câmeras (id, facing, modos resolução × fps), `concurrent` real (do S3) e encoders H.264 disponíveis.

## Leia só isto
`docs/spikes/S3.md` (veredito + "Limites reais do dual neste aparelho"). `docs/protocol-vectors.json` (vetor `hello_pair` → formato de `caps`). `docs/CHEATSHEET.md` (Padrões).

## Contexto embutido
- Formato (vetor `hello_pair`): `"caps":{"cameras":[{"id":"0","facing":"back","modes":[{"w":1920,"h":1080,"fps":[30]}]}],"concurrent":false,"audio":true,"codecs":["h264"]}`.
- Veredito S3 (Samsung SM-G781B): CameraX (única) + Camera2 (dual, Fase 7); 1080p30 estável (29,7 fps, jitter <1); **60 fps NÃO é oferecido** (`offers60=false`) — não incluir 60 nos `modes`; o dual **funciona** neste aparelho (S3 T4: back+front 1080p cada).
- `concurrent`: valor **real** do S3 (neste aparelho = true) — mas a Fase 2 implementa só câmera única: registre em `PROGRESS.md` (*Observações*) a divergência (capacidade do hardware × o que o app expõe). Não decida sozinho o que enviar; o padrão inicial é reportar a capacidade real e o usuário valida no GATE.
- Artifacts CameraX: use a versão do spike S3; se a versão não estiver confirmável no S3, use a **estável atual da documentação oficial** (não invente versão) e registre.
- Encoder: `MediaCodecList` → nomes dos encoders H.264 (diagnóstico; a escolha é do F2-T08).
- `audio`: capability true (o envio de áudio vem na Fase 8).

## Passos
1. Confira a versão CameraX (S3/docs oficiais) e adicione os artifacts ao `build.gradle`.
2. `probe(context): String` (JSON): `CameraManager` para id/orientação/modes; filtra modos (largura×altura, faixas de fps → valores padrão 30); inclui `codecs:["h264"]` e o encoder H.264 encontrado (campo extra de diagnóstico, tolerado pelo servidor — campos extras são ignorados).
3. IT-2.04 (instrumentado): pelo menos 1 câmera `back` com modo 1080×30; `concurrent` igual ao do S3 para este aparelho; encoder H.264 presente.
4. Para filtrar uma classe instrumentada, use `am instrument` (o Gradle `--tests` filtra testes JVM, não `connectedDebugAndroidTest`). Com os APKs debug + androidTest instalados no `RXCT800A2HR`, rode:
   `adb -s RXCT800A2HR shell am instrument -w -e class com.localcamera.app.camera.CapabilitiesProbeTest com.localcamera.app.test/androidx.test.runner.AndroidJUnitRunner`.
5. (A) Humano revisa `caps`/`concurrent` em `adb -s RXCT800A2HR logcat -d -s CapabilitiesProbeTest:I` e valida o valor medido (anote a decisão).
