# F2-T01 — Capacitor e deep link (`localcamera://connect`)

**Fase:** 2 · **Executor:** A+H · **Depende de:** F1-GATE · **Tempo:** ~3 h · **Contexto estimado:** ~10k tokens

## Objetivo
O app recebe a URI de pareamento `localcamera://connect?...` tanto ao ser aberto por ela (frio) quanto já aberto (quente): `@capacitor/app` entrega a URL ao JS (`appUrlOpen`), o manifest é conferido (retrato, singleTask, intent-filter) e a URI fica armazenada sem o token. As telas que consomem a URI vêm em F2-T03.

## Leia só isto
`docs/ui/mobile.md` §3.13 (tema, ícone e notificação) e §3.1 (navegação). Arquivos atuais: `mobile/capacitor.config.ts`, `mobile/android/app/src/main/AndroidManifest.xml`, `mobile/src/main.tsx`.

## Contexto embutido
- O manifest (desde F0-T03) já tem: `launchMode="singleTask"`, `screenOrientation="portrait"`, `allowBackup="false"` e intent-filter `VIEW`/`BROWSABLE` com `scheme=localcamera` `host=connect`. **Confira — não altere sem motivo** (singleTask é o que permite receber a URI com o app já aberto).
- `@capacitor/app` 8.1.2 já está no `mobile/package.json`. API: `App.addListener("appUrlOpen", ...)` — **confirme** o nome/assinatura em `mobile/node_modules/@capacitor/app` (`.d.ts`) antes de usar; não invente.
- Segredo: nunca logar o token inteiro (máx. 4 caracteres).
- A URI ainda **não** é validada aqui (F2-T05a valida no Kotlin; a UI consome em F2-T03) — armazene a string bruta.
- ST-2.05 (WebView sem debug remoto em release): o Capacitor só ativa `setWebContentsDebuggingEnabled(true)` em builds debug — **confirme** lendo a fonte em `mobile/node_modules/@capacitor/android/capacitor/src` e registre o achado no relatório.

## Passos
1. Confira o manifest (intent-filter, singleTask, retrato). Se faltar algo listado acima, edite no mínimo e justifique na mensagem do commit.
2. Leia o `.d.ts` do `@capacitor/app`; registre o listener `appUrlOpen` em `main.tsx` (antes do React montar) → `setPendingDeepLink(url)`.
3. `deep-link.ts`: `setPendingDeepLink/getPendingDeepLink/clearPendingDeepLink` + `logDeepLink(url)` (loga só scheme, host, porta e os 4 primeiros chars do token).
4. `capacitor.config.ts`: confira `appId`/`webDir`; só acrescente campos do bloco `android` se a documentação oficial (ou `.d.ts`) indicar que a URI depende deles — o intent-filter já cobre o resto; não adicione por hábito.
5. ST-2.05: grep `setWebContentsDebuggingEnabled` na fonte do `@capacitor/android`; registre o achado.
6. Build, sync, install:
   ```powershell
   pnpm --filter mobile build
   pnpm --filter mobile exec cap sync android
   cd mobile/android; .\gradlew.bat :app:assembleDebug; cd ..\..
   adb -s <serial> install -r mobile\android\app\build\outputs\apk\debug\app-debug.apk
    (`<serial>`: `adb devices` — Samsung `RXCT800A2HR` ou Moto G (5) `0030261879`.)
   ```
7. (A) Humano + agente: com o app fechado E com ele aberto, dispare no aparelho conectado:
   ```
   adb -s <serial> shell "am start -a android.intent.action.VIEW -d 'localcamera://connect?v=1&hosts=127.0.0.1&port=48650&token=00112233445566778899aabbccddeeff&pc=11111111-1111-4111-8111-111111111111&name=PC' com.localcamera.app"
    **Aspas obrigatórias**: o `adb shell` junta os argumentos num `sh` remoto — sem as aspas simples internas, o `&` divide o comando e o app recebe só `?v=1` (armadilha confirmada na execução).
   ```
   Confirme que o app abre/foca e que a URI aparece no log com token mascarado.
