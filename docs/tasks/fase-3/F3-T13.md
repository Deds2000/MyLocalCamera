# F3-T13 — Comandos e eventos Tauri (ponte com o `lc-server`)

**Fase:** 3 · **Executor:** agente · **Depende de:** F3-T01 · **Tempo:** ~3 h · **Contexto estimado:** ~14k tokens

## Objetivo
O `lc-server` da Fase 1 rodando dentro do desktop (estado gerenciado do Tauri), com comandos tipados e validados no Rust (`get_connection_info`, `regenerate_token`, `approve`, `reject`, `list_trusted`, `revoke_trusted`, `get_health`) e eventos `session://connection`, `session://stats`, `trust://pending`, mais o wrapper tipado do frontend `desktop/src/lib/tauri.ts` com mock para web/testes.

## Leia só isto
Só este cartão +, **antes de wirear**, `crates/lc-server/src/events.rs` (variantes de `ServerEvent`), `crates/lc-server/src/lib.rs` (API de `ServerHandle`) e `crates/lc-server/src/trust/{approval,store}.rs` (rotação de token e revogação). Não invente API — se algo não existir, registre em Observações.

## Contexto embutido
- API atual de `ServerHandle` (Fase 1): `local_port()`, `trust() -> Arc<Mutex<TrustStore>>`, `sessions()`, `decide(request_id, Decision) -> bool`, `events() -> &mut mpsc::Receiver<ServerEvent>`, `active_connections()`. Os eventos de `ServerEvent` (ex.: pareamento, aprovação solicitada/resolvida, conexão aberta/fechada, stats) estão em `events.rs` — **leia antes de mapear**.
- Fatos do protocolo (CHEATSHEET): porta padrão `48650`; URI de pareamento `localcamera://connect?v=1&hosts=IP1,IP2&port=48650&token=<32 hex>&pc=<pcId>&name=<nome>`; aprovação 30 s; estatísticas para a UI **no máximo a cada 500 ms** (o agregador já existe no `lc-server` — F1-T10); o PC guarda só o **SHA-256** da chave do dispositivo (`trusted_devices[]`: `deviceId`, `name`, `keyHash`, `firstSeen`, `lastSeen`, `lastIp`); token rotaciona após cada pareamento e em "Regenerar"; códigos `reason`: `bad_token`, `not_approved`, `revoked`, `busy`, `version_mismatch`, `bad_audio_ticket`, `timeout`, `protocol_error`.
- Capabilities atuais: `core:default` + `opener:default` em `desktop/src-tauri/capabilities/default.json`. Adicionar **só** o que for usado (controles de janela da titlebar: minimize/maximize/close/set-state...). Os nomes exatos das permissões estão em `desktop/src-tauri/gen/schemas/desktop-schema.json` — **não adivinhe**.
- Frontend: `@tauri-apps/api` (invoke/listen) já é dependência. Wrapper tipado com **mock** para fora do Tauri (web/testes): detectar ambiente Tauri (`window.__TAURI_INTERNALS__`) e cair no mock injetável.
- Dados do servidor: `data_dir` = app data dir do Tauri → estado de pareamento em `<data_dir>/trust.json` (formato do `TrustStore`). O harness de teste do agente lê o token de pareamento **deste arquivo** para alimentar o `mock-sender` — sem imprimir o segredo (máx. 4 chars).

## Passos
1. `server.rs`: no setup, criar o `lc-server` (config padrão da Fase 1; porta 48650; `data_dir` = app data dir) e guardar em `tauri::State`. Porta ocupada → o servidor deve expor a **porta efetiva** (conferir o comportamento do `lc-server` quando o bind falha; se não existir, tratar no setup com a porta sugerida — registrar).
2. `events_pump.rs`: task tokio lendo `ServerHandle::events()` → `app.emit(...)`:
   - `session://connection` — mudança de estado da conexão/pareamento (payload tipado: estado, nome/modelo/transporte do aparelho **sem segredos**, código de erro);
   - `session://stats` — o agregador de 500 ms do `lc-server` (fps, bitrate, RTT, perdidos);
   - `trust://pending` — pedido de aprovação (metadata: nome, modelo, IP do peer — IP não é segredo; **nunca** token/chave/ticket).
3. `commands.rs` (validar **tudo** no Rust; erro tipado, sem panic, sem segredo na mensagem):
   - `get_connection_info -> { port, effectivePort, interfaces: [{name, ip, isVirtual}], qrcodeUri, pairCodeMasked, pcId, name }` — o token **só** entra na `qrcodeUri` (para o QR); `pairCodeMasked` = máx. 4 chars + `••••`;
   - `regenerate_token` — rotaciona o token de pareamento (API do `TrustStore` — conferir);
   - `approve({ requestId, mode: once|always })` / `reject({ requestId })` — via `ServerHandle::decide`; **sem pedido pendente → erro** (ST-3.06);
   - `list_trusted -> [{ deviceId, name, model?, lastSeen, lastIp }]`;
   - `revoke_trusted({ deviceId })` — deviceId validado (formato/len);
   - `get_health -> { server: {state: listening|altPort|failed, port, effectivePort}, ...stubs "em breve" }` (os stubs alimentam a F3-T12).
4. `lib.rs`: registrar comandos + state + pump; no shutdown, cancelar pedido de aprovação pendente (recusado; base da FT-3.10 — `ApprovalManager` tem `cancel`, conferir).
5. `capabilities/default.json`: adicionar as permissões de janela usadas (nomes do schema gerado).
6. `lib/tauri.ts`: `invoke<T>(cmd, args)`, `listen<T>(event, handler) -> unlisten`, tipos dos payloads; mock injetável para testes/web.
