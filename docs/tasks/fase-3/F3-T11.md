# F3-T11 — Estados do preview, chips e barra de ferramentas

**Fase:** 3 · **Executor:** agente · **Depende de:** F3-T10 · **Tempo:** ~3 h · **Contexto estimado:** ~14k tokens

## Objetivo
Estados completos do preview (§2.5.2), chips de status (§2.5.3) a ≤ 2 Hz, barra de ferramentas (§2.5.4) com atalhos de teclado (§2.9), espelho/giro com **efeito local imediato** (o `SET` no celular é Fase 6) e tela cheia do preview.

## Contexto embutido
§2.5.2 — Estados do preview:

| Estado | O que aparece | Overlays |
|---|---|---|
| `empty` | `EmptyState` com QR (§2.3) | Nenhum |
| `connecting` | `bg-raised`, spinner e "Conectando…" | Nenhum |
| `pending` | escudo + "Aguardando sua aprovação" + botão que reabre o diálogo | Nenhum |
| `streaming` | Vídeo | Chips + barra |
| `reconnecting` | **último quadro congelado** + escurecimento 50% (opacidade, sem blur) + spinner + "Reconectando… (etapa)" | chips em `warn` |
| `error` | `TriangleAlert` + título/mensagem **por código** (`common.errors.*`) + ação (Tentar novamente / Parear de novo) | Nenhum |
| `paused` | invisível ao usuário; retoma < 200 ms | — |

§2.5.3 — Chips (canto sup. esquerdo, margem 8 px, gap 6 px): 1) **AO VIVO** (ponto pulsando; "RECONECTANDO" em `warn`); 2) **Resolução·fps** (`1080p · 30`); 3) **Bitrate** (`8,0 Mbps`); 4) **Latência** (RTT PING/PONG) — `warn` **> 80 ms**, `danger` **> 200 ms**; 5) **Perdidos** (janela de 10 s) — **só aparece se > 0**. Valores em fonte `mono` (tabular), atualização **≤ 2 Hz**.

§2.5.4 — Barra (pílula centralizada, 16 px acima da base do preview): botões 36 px, ícone 20 px, tooltip **nome + atalho**; auto-oculta após 3 s **só em tela cheia** (reaparece com o mouse).

| # | Ação | Ícone | Atalho | Fase 3 |
|---|---|---|---|---|
| 1 | Espelhar | `FlipHorizontal2` | `M` | **funcional** (local, PC; `aria-pressed`) |
| 2 | Girar 90° | `RotateCw` | `R` | **funcional** (local, PC; 0→90→180→270→0) |
| 3 | Alternar câmera | `SwitchCamera` | `C` | **desabilitado + tooltip** (celular — Fase 6) |
| 4 | Trocar principal/miniatura | `PictureInPicture2` | `S` | **desabilitado + tooltip** (PiP — Fase 7) |
| 5 | Tela cheia do preview | `Maximize`/`Minimize` | `F`/`F11` | **funcional** (`Esc` sai) |
| 6 | Mudo | `Mic`/`MicOff` | `Shift+M` | **desabilitado + tooltip** (Fase 8) |

§2.9 — Atalhos (tabela completa): `M`, `R`, `C`, `S`, `F`/`F11`, `Esc`, `Shift+M`, `Ctrl+,`, `Ctrl+1…4`. **Atalhos de tecla única só valem quando o foco não está em campo de texto.** (`Ctrl+` pertence ao painel — F3-T14a2.)

Espelho/rotação em Fase 3: atualizam o slice `ui` (estado local do PC) → o `compose` (F3-T08) lê `userRotation`/`mirror` → efeito **imediato**, sem rede (o `SET` no celular é Fase 6).

Tela cheia (§2.5.6): o preview **preenche a janela** (a janela não vira tela cheia do sistema), fundo preto, auto-ocultar da barra; `Esc`/`F`/`F11` saem.

## Passos
1. `useShortcuts.ts`: keydown global; guarda: foco em `input/textarea/select/[contenteditable]` → **ignorar** atalhos de tecla única (UT-3.24); mapa §2.9; `preventDefault` nos capturados; atalhos com botão desabilitado → sem efeito.
2. `PreviewArea`: switch por `connection.state` (+ sessão) → os 7 estados; `reconnecting` mantém o último quadro no canvas (não limpar) + overlay 50% opacidade + spinner + etapa; `error` mapeia **código** → `common.errors.*` + ações (Tentar novamente = reabrir/reconectar via comando existente; Parear de novo → aba Conexão).
3. `PreviewOverlays`: chips (só slice `stats` — seletor estreito); latência com thresholds 80/200 ms; perdidos só se > 0.
4. `Toolbar`: pílula com os 6 botões (3 desabilitados + tooltip com o motivo/fase); tooltips nome + atalho; `aria-pressed` no espelhar; auto-ocultar 3 s **apenas** em tela cheia.
5. Espelhar/girar: mutações no slice `ui` → pipeline (o `compose` consome; já integrado na F3-T09 via `preview.rs` — conferir como o Rust lê o estado; se ainda não lê, expor `set_presentation` mínimo no Rust — registrar).
6. Tela cheia: estado no slice `ui`; preview ocupa a janela; atalhos `F`/`F11`/`Esc`.
7. Toast de recuperação de decodificação ("Imagem retomada" — `desktop.errors.decode`): 1 toast por rajada, sem spam (parte UI da FT-3.01) — evento do decodificador (F3-T07) → toast.
