# F3-T09 — Preview (estratégia B: JPEG do Rust)

**Fase:** 3 · **Executor:** agente · **Depende de:** F3-T08, F3-T14a · **Tempo:** ~3 h · **Contexto estimado:** ~14k tokens

## Objetivo
Preview fluido pela estratégia vencedora do S5 — **B (JPEG reduzido gerado no Rust)**: o Rust pega o quadro composto (1920×1080 NV12, F3-T08), gera **JPEG ~960×540 a 30 fps do mesmo quadro composto** e envia ao frontend, que desenha no canvas via `createImageBitmap`, com fila limitada (descarta o mais antigo), pausa quando a janela está oculta e **sem alocações por quadro no JS** (reutilizar buffers).

## Leia só isto
Só este cartão + `docs/spikes/S5.md` (seção "Veredito: B" e "Notas de implementação") + `desktop/src-tauri/src/compose/mod.rs` (saída do compose).

## Contexto embutido
S5=B (RTX 3090, fixture 1080p, 2026-10-29): fps 29.77 / drops 0 · **0.653 MB/s no Channel** (~22 KB/frame) · latência p50/p95 **10/14 ms** · memória 29→37 MB flat · GPU 1.1%.

**Notas do S5 (importantes para a implementação):**
- No protótipo (Tauri 2.12.4), `tauri::ipc::Channel<Vec<u8>>` chegou ao frontend como **array JSON de números** (overhead ~3–5×); o protótipo converteu no recebimento e **ainda assim** sustentou 30 fps. No produto: **conferir na doc da versão em uso** (Cargo.lock / `node_modules/@tauri-apps/api`) o caminho binário documentado e mais barato (Channel base64, event com ArrayBuffer, etc.), **medir** e registrar a decisão em `PROGRESS.md` (Observações). Não invente API.
- JPEG do produto: 960×540; qualidade calibrada para manter média ~22 KB/frame (o S5 usou ffmpeg `-q:v 5`; com a crate `image` (feature jpeg) ajustar o quality e **medir** — registrar).
- Armadilhas: `ImageBitmap` **precisa** de `close()` (senão vaza memória de GPU); DPI 125%/150% borra o canvas se `devicePixelRatio` não for tratado (canvas físico = CSS × dpr); timers do WebView2 são limitados em janela oculta — o loop de desenho é dirigido pela **chegada dos frames** (IPC), não por timer JS.

## Passos
1. **Rust** (`preview.rs`): task tokio por sessão: consumir o quadro composto → downscale 960×540 (regra de amostragem documentada — nearest ou bilinear; registrar) → JPEG → enviar pelo transporte decidido (passo 2). Controlar ritmo de 30 fps (não enviar mais que 1/frame/33 ms; descartar o composto mais antigo se atrasar). Expor `pause()`/`resume()` (janela oculta — F3-T10 liga os eventos; aqui a API).
2. **Transporte**: decidir conforme S5 (medir as opções documentadas; registrar a escolha).
3. **Player** (`preview-player.ts`): ring buffer de ~4 frames recebidos; overflow → **descartar o mais antigo** (UT-3.09); ao ter frame novo: `createImageBitmap(buffer)` → desenhar no canvas (escala `devicePixelRatio`; `imageSmoothing` conforme) → `bitmap.close()` **após** o draw; reutilizar buffers (sem `new` por quadro); expor `fps` medido (uso: chips F3-T11 + instrumentação F3-T17) e timestamps de draw (F3-T17).
4. `PreviewCanvas.tsx`: canvas montado com `ref`; o player desenha **imperativamente** (nenhum `setState` por quadro — §4).
5. Pausa: `pause()` limpa a fila e **não** limpa o canvas (segura o último quadro — FT-3.03); `resume()` retoma no próximo frame (< 200 ms, F3-T10 mede).
6. IT-3.01 (pipeline completo headless): mock-sender `pattern1080.h264` → servidor → decoder → compose → pump do preview; teste de integração Rust asserindo **ordem e continuidade** dos AUs/índices do padrão (sem saltos) + e2e com o app dev + screenshot do canvas (complementar, agente via UIA).

## Não faça
- Não usar WebCodecs (estratégia A descartada no S5 — ADR 0005).
- Não passar frames pelo estado do React (nenhum `setState` por quadro).
- Não esquecer `close()` do `ImageBitmap`.
- Não depender de timer JS para o loop de frames (chegada via IPC).
- Não logar conteúdo de quadro.
