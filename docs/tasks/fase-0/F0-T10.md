# F0-T10 — (opcional) Playwright para o catálogo de componentes

**Fase:** 0 · **Executor:** agente · **Depende de:** F0-T02, F0-T03 · **Tempo:** ~1,5 h · **Contexto estimado:** ~5k tokens

## Objetivo
Deixar pronta a infraestrutura de **regressão visual**: Playwright abrindo o app no navegador (sem Tauri/Capacitor) e comparando capturas. O catálogo real (`?catalog`) só existe nas Fases 2/3; aqui basta um teste de captura da página inicial.

## Leia só isto
Documentação oficial do Playwright (web) para confirmar `webServer` e `toHaveScreenshot`.

## Arquivos
| Ação | Caminho |
|---|---|
| criar | `playwright.config.ts` (raiz), `e2e/smoke.spec.ts` |
| editar | `package.json` (script `e2e`), `.gitignore` (`test-results/`, `playwright-report/`) |

## Passos
1. `pnpm add -Dw @playwright/test` e `pnpm exec playwright install chromium`.
2. `playwright.config.ts`: dois *projects* (`desktop` em 960×640 e 1280×800; `mobile` em 390×844), `webServer` iniciando o `vite` de cada app (`pnpm --filter desktop exec vite --port 1420`, `pnpm --filter mobile exec vite --port 5173`; `reuseExistingServer: true`), `snapshotDir: "e2e/__snapshots__"`.
3. `e2e/smoke.spec.ts`: abre cada app e faz `await expect(page).toHaveScreenshot("home.png", { maxDiffPixelRatio: 0.01 })`.
4. Gere as capturas-base: `pnpm exec playwright test --update-snapshots`; rode de novo sem `--update-snapshots` e confirme que passa.
5. Script `"e2e": "playwright test"` no `package.json` da raiz. **Não** inclua no `ci.ps1` ainda (anotar em Observações para a Fase 2).

## Verificação
```powershell
pnpm run e2e 2>&1 | Select-Object -Last 15
```
Saída esperada: testes passam; pasta `e2e/__snapshots__` com as capturas.
