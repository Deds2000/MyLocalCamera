# F0-S2 — Spike S2: canal Frame Server ↔ app

**Fase:** 0 · **Executor:** agente+humano · **Depende de:** F0-S1 · **Tempo:** ~1–2 dias · **Contexto estimado:** ~9k tokens

## Objetivo
Definir **como o app entrega frames à DLL da câmera virtual** (que roda no Frame Server, em outra conta/sessão) **sem rodar o app como administrador**: *named pipe* com DACL, ou memória compartilhada `Global\`.

## Leia só isto
`docs/spikes/S1.md` (veredito e notas de como a DLL foi instalada) e `spikes/s1/NOTAS.md`.

## Contexto embutido
- Carga: 1080p30 NV12 = 3 110 400 bytes/quadro ≈ **93 MB/s**.
- Perguntas a responder: (1) o pipe criado por um usuário comum pode ser aberto pela conta do Frame Server? (2) o usuário comum consegue criar memória compartilhada em `Global\`? (3) vazão e latência; (4) o app percebe quando a DLL conecta/desconecta?; (5) recuperação ao matar app/Frame Server.
- **Confirme na documentação** qual conta/SID o serviço Frame Server usa (não suponha).
- Protótipos ficam em `spikes/s2/` (descartáveis).

## Divisão de trabalho
**Agente:** escrever os protótipos (servidor de pipe em Rust com DACL; ajuste mínimo na DLL do S1 para conectar ao pipe; gerador de quadros NV12 sintéticos; medidor). **Humano:** rodar como usuário comum, com um segundo usuário do Windows e (se possível) outra máquina na rede.

## Passos
### Agente
1. Em `spikes/s2/pipe-server` (crate Rust, **fora** do workspace principal ou como membro só do spike): crie o *named pipe* `\\.\pipe\LocalCameraSpike` com `PIPE_REJECT_REMOTE_CLIENTS` e uma **DACL** que concede acesso ao usuário atual **e** à conta do Frame Server (descubra o SID/nome correto). Use a crate `windows` (confirme os nomes de função em docs.rs/Microsoft Learn). Envia quadros NV12 sintéticos a 30 fps com cabeçalho `{w:u32,h:u32,format:u32,seq:u64,ptsUs:u64}`.
2. Ajuste uma **cópia** do código da DLL do S1 em `spikes/s2/dll` para conectar como cliente ao pipe e exibir os quadros recebidos (com fallback para o padrão de teste).
3. Escreva `spikes/s2/shm-server` equivalente usando `CreateFileMapping` em `Global\LocalCameraSpike` + evento de sinalização, e a variante da DLL que lê dele.
4. Medidor: registre por 60 s: quadros enviados/lidos, perdidos, latência escrita→leitura (p50/p95) e CPU dos dois lados (Gerenciador de Tarefas/`Get-Counter`).
5. Crie `docs/spikes/S2.md` (modelo abaixo).

### Humano
6. Rode os protótipos **como usuário comum** (não elevado) e preencha as tabelas. Para os testes de segurança, use um segundo usuário local e, se possível, outro PC.
7. Devolva as tabelas ao agente.

### Agente
8. Preencha `docs/spikes/S2.md` e crie `docs/adr/0003-canal-frames-vcam.md` (**aceito**).

## Não faça
- Não rode o servidor como administrador para "fazer funcionar" (isso invalida o teste).
- Não use TCP/UDP localhost sem avaliar a segurança (o protocolo do produto não deve expor frames na rede).
- Não coloque código do spike fora de `spikes/s2/`.
